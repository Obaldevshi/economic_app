# Timeweb: домены

1. Используй домен и Apps из запроса/контекста. Если схема не задана, предложи `<root>` и `www.<root>` для web, `api.<root>` для API; не спрашивай повторно уже указанные значения.
2. Для покупки домена покажи текущую стоимость и получи согласие. Не добавляй платный SSL, балансировщик и другие услуги.
3. Привяжи согласованные домены к соответствующим Apps. Сначала проверь существующие DNS-записи, чтобы не создавать дубли и не затронуть посторонние сервисы. Дождись HTTPS.
4. Сохрани tech-домены до проверки новых адресов. Проверь API `/health` и `/ready` по новому URL.
5. Обнови `CORS_ORIGINS` API: нужные web origins и `http://localhost:3000`, если используется локальный web.
6. Обнови `BASE_URL` и `BASE_URL_WEB` в локальном env на `https://api.<root>/api/v1`. Web требует новой сборки: если она запрошена — выполни `make build-web-prod`, иначе запроси готовую сборку. Опубликуй по согласованному способу из `../timeweb-deploy-web/SKILL.md`.
7. Сообщи финальные URL, выполненные проверки и блокеры. Файл прогресса обновляй только если он ведётся.

Если публичный DNS обновился, а проблема осталась лишь в одной сети, проверь кэш/другую сеть; не пересоздавай Apps без причины.
