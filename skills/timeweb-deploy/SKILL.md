# Развёртывание в Timeweb

1. Используй текущий запрос, существующие URL/ресурсы и `artifacts/timeweb-progress.md`, если он уже ведётся. Отсутствие файлов не блокирует размещение.
2. Перед первым размещением выполни `$13-check-api-timeweb`, если актуальная сверка ещё не проведена. После небольшого изменения сверяй только затронутое; отчёт в файле не обязателен. Устрани критические блокеры перед соответствующим этапом.
3. Убедись, что нужный код есть в выбранной GitHub-ветке, доступной Timeweb. Не отправляй изменения в случайный репозиторий или ветку.
4. До создания платного ресурса покажи актуальный тариф и стоимость и получи согласие. Уже согласованное действие не согласовывай повторно. Существующие подходящие ресурсы переиспользуй.
5. Не проси секреты в чате и не сохраняй их в git/отчётах. Используй настройки Timeweb и локальный env.
6. Выполни только запрошенные этапы:
   - `../timeweb-deploy-api/SKILL.md` — PostgreSQL и API;
   - `../timeweb-deploy-web/SKILL.md` — web;
   - `../timeweb-domains/SKILL.md` — домены, если нужны.
7. Статусы и публичные URL сообщай кратко. Создай `artifacts/timeweb-progress.md` по `assets/progress.template.md` только по просьбе сохранить прогресс; существующий журнал можно обновить.

API собирает Timeweb по `init-api/Dockerfile`. Web размещается из готового `init-app/build/web`. Если пользователь запросил сборку, выполни её без повторного разрешения; иначе используй предоставленную сборку. Не добавляй landing, TMA, магазины, VPS, балансировщик и другие услуги вне запроса.
