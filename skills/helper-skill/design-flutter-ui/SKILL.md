# UI из готовых компонентов

Обязательная поддержка mobile/web, способы ввода и сохранение состояния при изменении ширины описаны в разделе «UI/UX в init-app» корневого `AGENTS.md`.

1. Прочитай запрос и ближайший экран. Определи расположение контента и основного действия в narrow и wide; карта экранов и отдельный документ не нужны.
2. Переиспользуй тему из `lib/app/theme/`, `AppDimensions`, `ScrollShell`, `AuthScrollScaffold`, `GlobalButton`, `GlobalTextFormField` и готовую навигацию.
3. Реализуй обе компоновки в общей фиче. Для простого экрана достаточно одного гибкого layout, если он подходит обеим ширинам; отдельные ветки создавай только для реальных различий. Переиспользуй общие формы, карточки и действия.
4. Для форм используй готовый `KeyboardInset`; не вводи конфликтующие вложенные scroll-контейнеры. Проверь по коду, что основное действие доступно при клавиатуре и на узком окне браузера.
5. Добавь нужные loading/empty/error/success состояния в обеих компоновках. API-запросы не выполняй в `build`.
6. Строки — в обе ARB-локали, assets — через существующий генератор. Выделяй widget для повторения или самостоятельного блока, не для каждой строки UI.
7. Сохраняй светлую/тёмную тему и лёгкие эффекты. Не добавляй blur, тяжёлые анимации, новый UI-kit или зависимости ради обычного экрана.
8. Просмотри обе компоновки затронутого сценария по правилам `AGENTS.md`. Генерация и запуски — по тем же правилам; обязательной отдельной приёмки mobile и web нет.
