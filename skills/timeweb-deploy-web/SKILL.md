# Timeweb: Flutter Web

1. Возьми доступный API URL из текущего контекста или существующего журнала. Обнови `BASE_URL` и `BASE_URL_WEB` в локальном env: HTTPS URL с `/api/v1`.
2. Используй готовый `init-app/build/web`. Если сборка запрошена, выполни `make build-web-prod` из `init-app/`; иначе передай эту команду пользователю, когда свежей сборки нет. После смены API URL нужна новая сборка.
3. Проверь наличие `build/web/index.html` и соответствие клиентского env целевому API. Не публикуй секреты и приватные адреса из env. Не запускай дополнительно analyzer, тесты и все мобильные сборки.
4. Для размещения через GitHub используй согласованную ветку. `build/` игнорируется: перед принудительным добавлением сборки покажи состав и получи согласие, если такой способ публикации ещё не согласован. Не коммить локальный исходный `.env`.
5. Создай/обнови Static App HTML/CSS/JS: директория сборки `/init-app/build/web`, build-команда и директория проекта пустые. Сверь опции с текущей панелью; для нового платного ресурса согласуй актуальную стоимость.
6. Добавь origin web-приложения в `CORS_ORIGINS` API. Дождись деплоя и передай публичный URL; явно различай статус хостинга и фактическую проверку UI/авторизации.
7. Обнови существующий журнал при наличии. Не создавай отдельный отчёт и не запускай настройку доменов без запроса.
