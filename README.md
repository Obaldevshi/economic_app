# Flutter + FastAPI: готовая база для новых приложений

Шаблон уже содержит авторизацию, профиль, CRUD категорий, адаптивный UI-kit, темы, локализацию, API-клиент и инфраструктуру backend. Новые функции добавляются на эту базу.

```text
AGENTS.md       # единые правила: структура фич и минимум сопутствующей работы
.agents/skills/ # реализация, исправления и необязательное планирование
init-app/       # Flutter Android / iOS / Web
init-api/       # FastAPI + PostgreSQL + Alembic
skills/         # helpers и отдельный деплой в Timeweb
```

## Разработка

Достаточно описать задачу:

```text
Добавь заметки: список, создание, редактирование и удаление.
Используй готовую структуру, подключи Flutter к FastAPI.
```

Можно явно вызвать `$10-add-feature` или `$10b-fix-feature`. Файл идеи, карта экранов, очередь и карточка функции не требуются. Агент выполняет согласованный объём без остановки на формальные этапы после каждой фичи.

Правила структуры — в [AGENTS.md](AGENTS.md). Flutter использует общие models/API/repositories и feature UI; новая фича вызывает конкретный repository из BLoC. FastAPI переиспользует существующие model/schema/repository/service/route и `BaseRepository`. Дополнительные use cases, DTO-копии и интерфейсы с одной реализацией не обязательны. Категории служат готовым образцом упрощённой фичи; auth/profile сохраняют прежние контракты. DI регистрируется вручную через GetIt.

Моки, тесты, demo-данные, отчёты и дополнительные документы не создаются автоматически. Планирование и ручной чек-лист — по необходимости или запросу. Приложение, анализаторы, тесты и сборки запускаются по запросу; необходимые генераторы — после изменения их входов.

## Запуск приложения

В `init-app/` один раз подготовьте зависимости и локальную конфигурацию:

```bash
cp assets/env/.env.example assets/env/.env
flutter pub get
```

Укажите адрес реального API с `/api/v1` в `BASE_URL` для телефона и `BASE_URL_WEB` для браузера. Не добавляйте секреты в клиентский env. Для браузера разрешите его origin в CORS API.

```bash
flutter run -d <device-id>
flutter run -d chrome --web-port 3000
```

Mock-режим удалён. Все экраны используют реальный API. Реализацию можно написать до запуска backend, но проверить API-взаимодействие без доступного сервера нельзя.

Генерация при изменении Retrofit/JSON/assets: `dart run build_runner build --delete-conflicting-outputs`. Для ARB: `flutter gen-l10n`. Для обычной правки UI или регистрации DI генерация не нужна.

Команды приложения и сборок — в [init-app/README.md](init-app/README.md), backend — в [init-api/README.md](init-api/README.md).
